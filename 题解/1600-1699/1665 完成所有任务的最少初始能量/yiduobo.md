1665.完成所有任务的最少初始能量

[力扣](https://leetcode-cn.com/problems/minimum-initial-energy-to-finish-tasks/)

这个题一开始其实没什么思路，老实说还是看到数据规模之后才想到了具体做法。题目中的任务数非常多，意味着只能使用O(n)或者O(nlogn)的做法，那么可选的算法就只有动态规划或者贪心了。

首先考虑动态规划。题目这里要求决定任务执行的顺序，那么这里的状态表示必须能清晰地体现出已完成任务的特性。直接储存显然是不行的，而按照某种规则排序后选择前i个的话，这里的某种规则实际上就等同于贪心了，因此动态规划在这里行不通。

接下来考虑贪心。明面上看起来一个任务只有三个指标：

1、准入能量minimum

如果按准入能量从大到小执行，只需要安排准入能量高的任务实际花费了大量的能量，而准入能量低的实际花费很少就行了。例如[10, 10]和[1, 9]，答案为11，先执行[1, 9]再执行[10, 10]。如果先执行[10, 10]的话就需要19点初始能量。

而按照准入能量从小到大执行的话，则可以安排准入能量低的任务实际花费大量的能量，而准入能量高的任务花费很少就行了。例如[1, 10]和[9, 9]，答案为10，先执行[1, 10]再执行[9, 9]。如果先执行[9, 9]的话就需要19点初始能量。

2、实际耗费能量actual

如果按实际耗费能量从大到小执行，只需要安排耗费能量高的任务准入能量低，而耗费能量低的任务准入能量高就行了。例如[10, 10]和[1, 11]，答案为11，先执行[1, 11]再执行[10, 10]。如果先执行[10, 10]的话就需要21点初始能量。

而按照实际耗费能量从小到大执行，则可以安排耗费能量低的任务准入能量也低，而耗费能量高的任务准入能量也高。例如[1, 1]和[9, 10]，答案为10，先执行[9, 10]再执行[1, 1]。如果先执行[1, 1]的话就需要11点初始能量。

3、上面二者的差值

观察上面的反例可以知道，如果使用二者差值作为贪心的标准，那么必然是按照差值从大到小执行。一时间想不出什么反例，说明这个贪心的规则可能是正确的，那么必须要给出证明。

不妨设两个任务的花费和准入分别为[a1, b1]和[a2, b2]，且b1 - a1 > b2 - a2，需要证明的就是若按照贪心的规则，先执行[a1, b1]之后无法再执行[a2, b2]，那么此时也必然满足先执行[a2, b2]后无法再执行[a1, b1]。

首先如果能执行[a1, b1]，那么能量的初始值x必须满足x >\= b1。在执行了[a1, b1]之后消耗了a1而无法继续执行[a2, b2]，那么就相当于x - a1 \< b2

如果先执行[a2, b2]之后还可以再执行[a1, b1]，那么x就需要满足x - a2 >\= b1

联立两个不等式可以发现

b1 + a2 \<\= x \< a1 + b2

观察头尾两项就有

b1 + a2 \< a1 + b2

移项后可以得到

b1 - a1 \< b2 - a2

这明显与最开始假设的b1 - a1 > b2 - a2产生了矛盾

换言之，在满足b1 - a1 > b2 - a2的情况下，贪心策略必然是最优的。

根据上面的结论，就可以将所有任务按准入能量与实际消耗能量的差值从大到小进行排序，然后一趟扫描。对于当前任务而言：

1、若当前剩下的能量不够了，就将当前剩余能量补足至当前任务的准入能量，并将这个差值累加到答案。若当前剩余能量足够，则不执行任何操作。

2、此时执行当前任务，此时需要用实际消耗的能量来更新当前剩余的能量。

遍历完成后，累加出来的答案就是最少的初始能量。

最后附上python代码：

```python
class Solution(object):
    def minimumEffort(self, tasks):
        """
        :type tasks: List[List[int]]
        :rtype: int
        """

        now = 0
        res = 0
        for actuail, minimum in sorted(tasks, key=lambda d:d[1] - d[0], reverse=True):
            if now < minimum:
                res += minimum - now
                now = minimum - actuail
            else:
                now -= actuail
        
        return res
```
