1703.得到连续K个1的最少相邻交换次数

[力扣](https://leetcode-cn.com/problems/minimum-adjacent-swaps-for-k-consecutive-ones/)

首先对于这个数据规模而言，交换操作必然是不能模拟执行的，而是需要统计出每个1所在的位置，然后通过这些位置相减来得到交换的次数。不妨设这些1所在位置形成的数组为p，那么可以明确的一点是，最终答案必然是从p中连续的k个值得来的，这个也不需要什么复杂的证明，因为在将不连续的1集合在一起的过程中必然是会出现1与1交换的场景的，这明显就是浪费。

既然直到了最终答案是由p中连续k个1计算出来的，那么就可以使用滑动窗口，从头开始每次选出p中连续的k个，然后计算使得这些位置相邻所需的最少操作次数。

现在的问题就变成了给出从小到大排好的k个数，问将这些数集中在哪个数的周围所需的代价最小。

之前应该有一道非常像的问题，但是记不清楚题号了。简单描述是数轴上从小到大排好的k个点，找出一个点满足该点到所有点的距离之和最小，而最终答案就是这些点最中间那一个。证明的方法就是从两侧往中间将这些点两两进行分组，可以发现对于每一组的点而言，如果答案点选择这两点之间，那么这两点产生的距离之和就是这两个点位置之差，而如果答案点选在了这两点之外，那么这两点产生的距离之和就必然大于这两个点的位置之差。综合起来，可以发现最中间那个点是出现在所有两两分组的点对之间的，因此选择最中间的点可以使得距离最小。

回到本体，这里不同之处在于并不是要将所有点聚集到一个位置，而是从这个位置开始向两侧开始一次排布。不过答案并没有产生变化，证明方法也是类似的。不妨设现在有一组点对(l, r)，其坐标分别为p[l]和p[r]。那么：

1、若聚集目标m选择在l和r之间，那么l的最终目的地就是p[m] - (m - l)，r的最终目的地就是p[m] + (r - m)，那么最终交换的代价时

p[m] - (m - l) - p[l] + p[r] - (p[m] + (r - m)) \= p[r] - p[l] + l - r

2、若聚集目标m选择在l的左侧，那么l的最终目的地就是p[m] + (l - m)，r的最终目的地就是p[m] + (r - m)，那么最终交换的代价就是

p[l] - (p[m] + (l - m)) + p[r] - (p[m] + (r - m)) \=

p[l] + p[r] - l - r + 2 \* (m - p[m]) \=

p[l] + (p[r] - p[l] + p[l]) - l + (l - l) - r + 2 \* (m - p[m]) \=

p[r] - p[l] + l - r + 2 \* (p[l] - l + m - p[m])

这里有一个隐藏条件就是p[l] - p[m] >\= l - m，这是有p的构造方式得来的。极限情况下，在原始字符串中从p[m]到p[l]都是紧紧相邻的1，那么就有p[m + 1] \= p[m] + 1，p[m + 2] \= p[m] + 2，以此类推，就有p[l] \= p[m] + l - m。而一旦p[m]到p[l]之间只有有一个0出现，那么由于这个0的影响p[l]就必然大于p[m] + l - m，因此这里必然满足p[l] - p[m] >\= l - m

换言之，这种情况下操作的代价必然大于等于情况1中操作的代价

3、若聚集目标m选择在r的右侧，那么l的最终目的地就是p[m] - (m - l)，r的最终目的地就是p[m] - (m - r)，类似的，写出最终交换的代价

p[m] - (m - l) - p[l] + p[m] - (m - r) - p[r] \=

2 \* (p[m] - m) + l - p[l] + r - p[r] \=

2 \* (p[m] - m) + (l - r + r) + (p[r] - p[l] - p[r]) + r - p[r] \=

p[r] - p[l] + l - r + 2 \* (p[m] - m + r - p[r])

由于p[m] - p[r] >\= m - r，因此这里的操作代价同样大于等于情况1中操作的代价

综合起来，就说明这里的目标点m依然应该选择在l与r之间，因此最终的目标点依然是这k个点最中间的那个点。对于k为奇数的情况有唯一的中点，而对于k为偶数的情况则可以任意选择二者之一，在这里为了方便计算，统一选择靠后的那个点作为目标点。

确定了聚集点之后，接下来就是如何计算总代价了。由于直接计算目标点会比较复杂，那么可以转化成两步来计算。首先计算所有点聚集到中心点所需的代价，然后计算将这些点从中心点分配到实际的目的地所需的代价，然后使用前者减去后者就是最终答案了。

这里做减法的原因是实际上这些点最终的目的地并不是聚集的中心点，而是从中心点两侧相邻排开的位置。如果计算的时候计算的是其聚集到中心点的代价，实际上就多计算了其真正目标点到中心点的代价。由于a移动到b与b移动到a是等价的，因此在这里可以减去将这些点从中心点分配到真正目标点的代价来消除多计算的这部分代价。

首先考察聚集到中心点的代价如何计算。滑动窗口最开始的k个点的总代价需要从两侧向中间枚举计算：

1、当k为奇数时，总代价为

p[k - 1] - p[0] + p[k - 2] - p[1] + ... + p[k / 2 + 1] - p[k / 2 - 1]

2、当k为偶数时，总代价为

p[k - 1] - p[0] + p[k - 2] - p[1] + ... + p[k / 2 + 1] - p[k / 2 - 2] + p[k / 2] - p[k / 2 - 1]

需要特别注意这里细微的差别

有了窗口初始值之后，需要考虑窗口化滑动起来之后如何计算这个代价。设当前区间为[l, r]，中心点为m，那么：

1、当k为奇数时：

窗口滑动前总代价为

cost[l, r] \=

p[r] - p[l] + p[r - 1] - p[l + 1] + ... + p[m + 1] - p[m - 1] \=

(p[r] + p[r - 1] + ... + p[m + 1]) - (p[l] + p[l + 1] + ... + p[m - 1])

窗口滑动后，区间变成了[l + 1, r + 1]，中心则变为m + 1，那么此时的代价为

cost[l + 1, r + 1] \=

p[r + 1] - p[l + 1] + p[r] - p[l + 2] + ... + p[m + 2] - p[m] \=

(p[r + 1] + p[r] + ... + p[m + 2]) - (p[l + 1] + p[l + 2] + ... + p[m])

对比滑动前后，可以发现

cost[l + 1, r + 1] \= cost[l, r] + p[r + 1] - p[m + 1] + p[l] - p[m]

2、当k为偶数时：

窗口滑动前总代价为

cost[l, r] \=

p[r] - p[l] + p[r - 1] - p[l + 1] + ... + p[m + 1] - p[m - 2] + p[m] - p[m - 1] \=

(p[r] + p[r - 1] + ... + p[m + 1] + p[m]) - (p[l] + p[l + 1] + ... + p[m - 2] + p[m - 1])

窗口滑动后，区间变成了[l + 1, r + 1]，中心则变为m + 1，那么此时的代价为

cost[l + 1, r + 1] \=

p[r + 1] - p[l + 1] + p[r] - p[l + 2] + ... + p[m + 2] - p[m - 1] + p[m +1] - p[m] \=

(p[r + 1] + p[r] + ... + p[m + 2] + p[m + 1]) - (p[l + 1] + p[l + 2] + ... + p[m - 1] + p[m])

对比滑动前后，可以发现

cost[l + 1, r + 1] \= cost[l, r] + p[r + 1] - p[m] + p[l] - p[m]

也就是说随着[l, r]的向后移动，无论k是奇数还是偶数，都可以通过移动之前区间所需的代价在O(1)的时间复杂度内获取到移动后区间所需的代价。

最后考虑将所有这k个点从聚集点m分配出去的代价：

1、当k为奇数时，分配的目标点分别为

m - k / 2, m - k / 2 + 1, ..., m - 1, m , m + 1, ..., m + k / 2 - 1, m + k / 2

分配产生的代价分别为

k / 2, k / 2 - 1, ... 1, 0, 1, ..., k / 2 - 1, k / 2

这里以0为中心是两个等差数列，那么总的代价就是

(k / 2 + 1) \* (k / 2)

2、k为偶数时，分配的目标点分别为

m - k / 2，m - k / 2 + 1, ..., m - 1, m, m + 1, ..., m + k / 2 - 1

需要注意由于这里默认m是两个中心点当中靠后的那一个，因此其右侧的目标点到m + k / 2 - 1就足够了。分配产生的代价分别为

k / 2, k / 2 + 1, ..., 1, 0, 1, ..., k / 2 - 1

抛开k / 2不看，这里同样是两个等差数列，那么总的代价也是

(k / 2 + 1) \* (k / 2)

不过还需要落单的k / 2，因此总代价就是

(k / 2 + 1) \* (k / 2) + k / 2

在窗口滑动的过程中计算聚合到中心点的最小代价之后，将其减去分配的代价就是最终答案了。

最后附上python代码：

```python
class Solution(object):
    def minMoves(self, nums, k):
        """
        :type nums: List[int]
        :type k: int
        :rtype: int
        """

        p = []
        for index, num in enumerate(nums):
            if num == 1:
                p.append(index)
        
        l = 0
        r = k - 1
        now = 0
        while l < r:
            now += p[r] - p[l]
            l += 1
            r -= 1
        
        res = now
        
        
        m = l
        l = 0
        r = k - 1
        res = now
        n = len(p)

        while r < n - 1:
            if k & 1:
                now += p[r + 1] - p[m + 1]
                now += p[l] - p[m]
            else:
                now += p[r + 1] - p[m]
                now += p[l] - p[m]
            res = min(res, now)
            l += 1
            r += 1
            m += 1
        
        res -= (1 + (k - 1) / 2) * ((k - 1) / 2)
        if k % 2 == 0:
            res -= k / 2
        
        return res
```
