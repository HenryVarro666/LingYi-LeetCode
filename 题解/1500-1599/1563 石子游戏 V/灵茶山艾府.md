# 动态规划：从 O(n^3) 到 O(n^2)（Python/Java/C++/Go）

> **[1563. 石子游戏 V](https://leetcode.cn/problems/stone-game-v/solutions/4008208/dong-tai-gui-hua-cong-on3-dao-on2pythonj-rlqz/) · Hard · 难度分 2087**

> **题目描述**
> 几块石子 **排成一行** ，每块石子都有一个关联值，关联值为整数，由数组 `stoneValue` 给出。
>
> 游戏中的每一轮：Alice 会将这行石子分成两个 **非空行**（即，左侧行和右侧行）；Bob 负责计算每一行的值，即此行中所有石子的值的总和。Bob 会丢弃值最大的行，Alice 的得分为剩下那行的值（每轮累加）。如果两行的值相等，Bob 让 Alice 决定丢弃哪一行。下一轮从剩下的那一行开始。
>
> 只 **剩下一块石子** 时，游戏结束。Alice 的分数最初为 **`0`** 。
>
> 返回 **Alice 能够获得的最大分数** <em>。</em>
>
> **示例 1：**
>
> ```
>
> 输入：stoneValue = [6,2,3,4,5,5]
> 输出：18
> 解释：在第一轮中，Alice 将行划分为 [6，2，3]，[4，5，5] 。左行的值是 11 ，右行的值是 14 。Bob 丢弃了右行，Alice 的分数现在是 11 。
> 在第二轮中，Alice 将行分成 [6]，[2，3] 。这一次 Bob 扔掉了左行，Alice 的分数变成了 16（11 + 5）。
> 最后一轮 Alice 只能将行分成 [2]，[3] 。Bob 扔掉右行，Alice 的分数现在是 18（16 + 2）。游戏结束，因为这行只剩下一块石头了。
> ```
>
> **示例 2：**
>
> ```
>
> 输入：stoneValue = [7,7,7,7,7,7,7]
> 输出：28
> ```
>
> **示例 3：**
>
> ```
>
> 输入：stoneValue = [4]
> 输出：0
> ```
>
> **提示：**
>
> - `1 <= stoneValue.length <= 500`
>
> - `1 <= stoneValue[i] <= 10⁶`

> **题解**
> ## 一、寻找子问题
>
> 在示例 1 中，我们要解决的问题（原问题）是：
>
> - 在 $\textit{stoneValue} = [6,2,3,4,5,5]$ 上能够获得的最大分数。
>
> 我们需要把数组分割成左右两段，枚举这一刀切在哪：
>
> - 分割成 $[6]$ 和 $[2,3,4,5,5]$，丢弃右段，问题变成在 $[6]$ 上能够获得的最大分数。
> - 分割成 $[6,2]$ 和 $[3,4,5,5]$，丢弃右段，问题变成在 $[6,2]$ 上能够获得的最大分数。
> - 分割成 $[6,2,3]$ 和 $[4,5,5]$，丢弃右段，问题变成在 $[6,2,3]$ 上能够获得的最大分数。
> - 分割成 $[6,2,3,4]$ 和 $[5,5]$，丢弃左段，问题变成在 $[5,5]$ 上能够获得的最大分数。
> - 分割成 $[6,2,3,4,5]$ 和 $[5]$，丢弃左段，问题变成在 $[5]$ 上能够获得的最大分数。
>
> 这些问题都是**和原问题相似的、规模更小的子问题**，可以用**递归**解决。
>
> ## 二、状态定义与状态转移方程
>
> 由于子问题都在 $\textit{stoneValue}$ 的连续子数组上，所以定义 $\textit{dfs}(i,j)$ 表示在 $\textit{stoneValue}$ 的子数组 $[i,j)$ 上能够获得的最大分数。这里用左闭右开区间表示子数组的下标范围，方便用前缀和计算子数组的和。
>
> 设 $\textit{stoneValue}$ 的**前缀和**数组为 $s$。关于 $s$ 数组的定义，请看 [前缀和](../../0300-0399/0303%20区域和检索%20-%20数组不可变/灵茶山艾府.md)。子数组 $[i,j)$ 的和为 $s[j]-s[i]$。
>
> 枚举把子数组 $[i,j)$ 分割成 $[i,k)$ 和 $[k,j)$，其中 $i < k < j$。
>
> 比较子数组 $[i,k)$ 的元素和与子数组 $[k,j)$ 的元素和：
>
> - 如果子数组 $[i,k)$ 的元素和更小，问题变成在 $\textit{stoneValue}$ 的子数组 $[i,k)$ 上能够获得的最大分数，即 $\textit{dfs}(i,k)$。再加上子数组 $[i,k)$ 的元素和（得分），更新 $\textit{dfs}(i,j)$ 的最大值。
> - 如果子数组 $[k,j)$ 的元素和更小，问题变成在 $\textit{stoneValue}$ 的子数组 $[k,j)$ 上能够获得的最大分数，即 $\textit{dfs}(k,j)$。再加上子数组 $[k,j)$ 的元素和（得分），更新 $\textit{dfs}(i,j)$ 的最大值。
> - 如果两个子数组的元素和相等，取 $\textit{dfs}(i,k)$ 和 $\textit{dfs}(k,j)$ 的最大值，加上子数组 $[i,k)$ 的元素和（得分），更新 $\textit{dfs}(i,j)$ 的最大值。
>
> **递归边界**：$\textit{dfs}(i,i+1)=0$。只剩下一块石子，游戏结束。
>
> **递归入口**：$\textit{dfs}(0,n)$，这是原问题，也是答案。
>
> ## 三、递归搜索 + 保存递归返回值 = 记忆化搜索
>
> 考虑到整个递归过程中有大量重复递归调用（递归入参相同）。由于递归函数没有副作用，同样的入参无论计算多少次，算出来的结果都是一样的，因此可以用**记忆化搜索**来优化：
>
> - 如果一个状态（递归入参）是第一次遇到，那么可以在返回前，把状态及其结果记到一个 $\textit{memo}$ 数组中。
> - 如果一个状态不是第一次遇到（$\textit{memo}$ 中保存的结果不等于 $\textit{memo}$ 的初始值），那么可以直接返回 $\textit{memo}$ 中保存的结果。
>
> **注意**：$\textit{memo}$ 数组的**初始值**不能等于要记忆化的值。例如初始值设置为 $0$，并且要记忆化的 $\textit{dfs}(i,j)$ 也等于 $0$，那就没法判断 $0$ 到底表示第一次遇到这个状态，还是表示之前遇到过了，从而导致记忆化失效。一般把初始值设置为 $-1$。不过，本题 $\textit{stoneValue}[i]>0$，除了递归边界，其余状态（要记忆化的值）均为正数，所以可以把初始值设置为 $0$。
>
> > Python 用户可以无视上面这段，直接用 `@cache` 装饰器。
>
> 关于记忆化搜索的原理，请看视频讲解 [动态规划入门：从记忆化搜索到递推【基础算法精讲 17】](https://www.bilibili.com/video/BV1Xj411K7oF/)，其中包含把记忆化搜索 1:1 翻译成递推的技巧。
>
> #### 答疑
>
> **问**：答案是否会超过 $32$ 位有符号整数的最大值？
>
> **答**：不会。设 $\textit{stoneValue}$ 的总和为 $S$。根据题目的数据范围，$S\le 5\times 10^8$。由于 Bob 总是会丢弃和最大的那一部分，所以一轮过后，剩下的石子个数不超过 $\dfrac{S}{2}$（减半）。所以两轮过后，剩下的石子个数不超过 $\dfrac{S}{4}$（减半再减半）。依此类推，设一共玩了 $m$ 轮，由等比级数求和公式可得，答案（以及任意状态值）不会超过
>
> $$
> \dfrac{S}{2} + \dfrac{S}{4} + \cdots + \dfrac{S}{2^m} = S\cdot\left(1 - \dfrac{1}{2^m}\right) < S\le 5\times 10^8
> $$
>
> ```python
> class Solution:
>     def stoneGameV(self, stoneValue: List[int]) -> int:
>         s = list(accumulate(stoneValue, initial=0))  # stoneValue 的前缀和
>
>         # 返回 Alice 在子数组 [i,j) 中获得的最大分数
>         @cache  # 缓存装饰器，避免重复计算 dfs（一行代码实现记忆化）
>         def dfs(i: int, j: int) -> int:
>             if j - i == 1:  # 只剩下一块石子，游戏结束
>                 return 0
>
>             res = 0
>
>             # 把子数组 [i,j) 分成 [i,k) 和 [k,j)
>             for k in range(i + 1, j):
>                 sum_l = s[k] - s[i]
>                 sum_r = s[j] - s[k]
>                 if sum_l < sum_r:  # Bob 丢弃 [k,j)，剩下 [i,k)
>                     score = dfs(i, k) + sum_l
>                 elif sum_l > sum_r:  # Bob 丢弃 [i,k)，剩下 [k,j)
>                     score = dfs(k, j) + sum_r
>                 else:  # sum_l = sum_r，由 Alice 决定丢弃哪边
>                     score = max(dfs(i, k), dfs(k, j)) + sum_l
>                 res = max(res, score)
>
>             return res
>
>         return dfs(0, len(stoneValue))
> ```
>
>
> #### 复杂度分析
>
> - 时间复杂度：$\mathcal{O}(n^3)$，其中 $n$ 是 $\textit{stoneValue}$ 的长度。由于每个状态只会计算一次，记忆化搜索的时间复杂度 $=$ 状态个数 $\times$ 单个状态的计算时间。本题状态个数为 $\mathcal{O}(n^2)$，单个状态的计算时间为 $\mathcal{O}(n)$，所以总的时间复杂度为 $\mathcal{O}(n^3)$。
> - 空间复杂度：$\mathcal{O}(n^2)$。保存多少状态，就需要多少空间。
>
> ## 四、1:1 翻译成递推
>
> 我们可以去掉递归中的「递」，只保留「归」的部分，即自底向上计算。
>
> $f[i][j]$ 的定义和 $\textit{dfs}(i,j)$ 的定义是完全一样的，都表示在 $\textit{stoneValue}$ 的子数组 $[i,j)$ 上能够获得的最大分数。
>
> 初始值 $f[i][i+1]=0$，翻译自递归边界 $\textit{dfs}(i,i+1)=0$。
>
> 答案为 $f[0][n]$，翻译自递归入口 $\textit{dfs}(0,n)$。
>
> #### 答疑
>
> **问**：如何思考循环顺序？什么时候要正序枚举，什么时候要倒序枚举？
>
> **答**：为了计算 $f[i][j]$，一方面，必须先把 $f[k][j]\ (k > i)$ 算出来，那么只有 $i$ 从大到小枚举才能做到；另一方面，必须先把 $f[i][k]\ (k < j)$ 算出来，那么只有 $j$ 从小到大枚举才能做到。
>
> ```python
> # ⚠有概率超时⚠
> class Solution:
>     def stoneGameV(self, stoneValue: List[int]) -> int:
>         n = len(stoneValue)
>         s = list(accumulate(stoneValue, initial=0))  # stoneValue 的前缀和
>         f = [[0] * (n + 1) for _ in range(n)]
>
>         for i in range(n - 2, -1, -1):
>             for j in range(i + 2, n + 1):
>                 # 把子数组 [i,j) 分成 [i,k) 和 [k,j)
>                 for k in range(i + 1, j):
>                     sum_l = s[k] - s[i]
>                     sum_r = s[j] - s[k]
>                     if sum_l < sum_r:  # Bob 丢弃 [k,j)，剩下 [i,k)
>                         score = f[i][k] + sum_l
>                     elif sum_l > sum_r:  # Bob 丢弃 [i,k)，剩下 [k,j)
>                         # 这里得到 sum_r 分，然后继续游戏，得分不超过 sum_r
>                         # 继续循环，得分不会比 sum_r * 2 还大
>                         if sum_r * 2 <= f[i][j]:
>                             break  # 最优性优化：继续循环不会让 f[i][j] 变大，所以跳出循环
>                         score = f[k][j] + sum_r
>                     else:  # sum_l = sum_r，由 Alice 决定丢弃哪边
>                         score = max(f[i][k], f[k][j]) + sum_l
>                     f[i][j] = max(f[i][j], score)
>
>         return f[0][n]
> ```
>
>
> #### 复杂度分析
>
> - 时间复杂度：$\mathcal{O}(n^3)$，其中 $n$ 是 $\textit{stoneValue}$ 的长度。
> - 空间复杂度：$\mathcal{O}(n^2)$。
>
> ## 五、优化：前后缀最大值
>
> 设 $p$ 是最大的满足 $s[k]-s[i]\le s[j]-s[k]$ 的下标 $k$。
>
> 设 $q$ 是最小的满足 $s[k]-s[i]\ge s[j]-s[k]$ 的下标 $k$。
>
> 状态转移方程可以表示为
>
> $$
> f[i][j] = \max
> \begin{cases}
> \max\limits_{k=i+1}^{p} (f[i][k] + s[k]-s[i])     \\
> \max\limits_{k=q}^{j-1} (f[k][j] + s[j]-s[k])     \\
> \end{cases}
> $$
>
> 把与 $k$ 无关的项提出来，得
>
> $$
> f[i][j] = \max
> \begin{cases}
> -s[i] + \max\limits_{k=i+1}^{p} (f[i][k] + s[k])     \\
> \phantom{-}s[j] + \max\limits_{k=q}^{j-1} (f[k][j] -s[k])     \\
> \end{cases}
> $$
>
> 定义前缀最大值数组 $\textit{preMax}[i][p] = \max\limits_{k=i+1}^{p} (f[i][k] + s[k])$。
>
> 由于 $[i+1,p]$ 的最大值可以拆分成 $[i+1,p-1]$ 的最大值与 $f[i][p] + s[p]$ 的最大值，所以有递推式
>
> $$
> \textit{preMax}[i][p] = \max(\textit{preMax}[i][p-1], f[i][p] + s[p])
> $$
>
> 定义后缀最大值数组 $\textit{sufMax}[q][j] = \max\limits_{k=q}^{j-1} (f[k][j] -s[k])$。
>
> 由于 $[q,j-1]$ 的最大值可以拆分成 $[q+1,j-1]$ 的最大值与 $f[q][j] -s[q]$ 的最大值，所以有递推式
>
> $$
> \textit{sufMax}[q][j] = \max(\textit{sufMax}[q+1][j], f[q][j] -s[q])
> $$
>
> 有了前后缀最大值，就能 $\mathcal{O}(1)$ 时间计算
>
> $$
> f[i][j] = \max(-s[i] + \textit{preMax}[i][p], s[j] + \textit{sufMax}[q][j])
> $$
>
> 现在还剩下一个问题：如何快速计算 $p$ 和 $q$？
>
> 由于 $j$ 越大，最大的满足 $s[k]-s[i]\le s[j]-s[k]$ 的下标 $k$ 也越大（或者不变），所以可以用**同向双指针**维护下标 $p$。对于 $q$，如果 $s[p]-s[i]= s[j]-s[p]$ 成立，则 $q=p$，否则 $q=p+1$。
>
> > **注**：$\textit{stoneValue}$ 中的元素都是正数，不会出现多个下标 $k$ 使得 $s[k]-s[i] = s[j]-s[k]$ 成立。
>
> 代码实现时，可以在跑双指针的同时计算 $\textit{preMax}$，从而把 $\textit{preMax}$ 优化成一个变量。
>
> ```python
> class Solution:
>     def stoneGameV(self, stoneValue: List[int]) -> int:
>         n = len(stoneValue)
>         s = list(accumulate(stoneValue, initial=0))  # stoneValue 的前缀和
>         f = [[0] * (n + 1) for _ in range(n)]
>         suf_max = [[-inf] * (n + 1) for _ in range(n + 1)]
>
>         for i in range(n - 1, -1, -1):
>             suf_max[i][i + 1] = -s[i]  # f[i][i+1] - s[i] = 0 - s[i] = -s[i]
>             pre_max = -inf  # 本题元素都是正数，也可以初始化成 0
>             k = i + 1
>             for j in range(i + 2, n + 1):
>                 while s[k] - s[i] <= s[j] - s[k]:
>                     pre_max = max(pre_max, f[i][k] + s[k])
>                     k += 1
>                 # 循环结束后 s[k] - s[i] > s[j] - s[k]
>                 q = k if s[k - 1] - s[i] != s[j] - s[k - 1] else k - 1
>                 f[i][j] = max(pre_max - s[i], suf_max[q][j] + s[j])
>                 suf_max[i][j] = max(suf_max[i + 1][j], f[i][j] - s[i])
>
>         return f[0][n]
> ```
>
>
> 观察代码，$f$ 的第一个维度可以优化掉。
>
> ```python
> class Solution:
>     def stoneGameV(self, stoneValue: List[int]) -> int:
>         n = len(stoneValue)
>         s = list(accumulate(stoneValue, initial=0))  # stoneValue 的前缀和
>         f = [0] * (n + 1)
>         suf_max = [[-inf] * (n + 1) for _ in range(n + 1)]
>
>         for i in range(n - 1, -1, -1):
>             suf_max[i][i + 1] = -s[i]  # f[i][i+1] - s[i] = 0 - s[i] = -s[i]
>             pre_max = -inf  # 本题元素都是正数，也可以初始化成 0
>             k = i + 1
>             for j in range(i + 2, n + 1):
>                 while s[k] - s[i] <= s[j] - s[k]:
>                     pre_max = max(pre_max, f[k] + s[k])
>                     k += 1
>                 # 循环结束后 s[k] - s[i] > s[j] - s[k]
>                 q = k if s[k - 1] - s[i] != s[j] - s[k - 1] else k - 1
>                 f[j] = max(pre_max - s[i], suf_max[q][j] + s[j])
>                 suf_max[i][j] = max(suf_max[i + 1][j], f[j] - s[i])
>
>         return f[n]
> ```
>
>
> #### 复杂度分析
>
> - 时间复杂度：$\mathcal{O}(n^2)$，其中 $n$ 是 $\textit{stoneValue}$ 的长度。对于固定的 $i$，虽然我们写了个二重循环（双指针），但由于最内层循环中 $k$ 增加一的**总**执行次数不会超过 $n$ 次，所以双指针的循环次数是 $\mathcal{O}(n)$ 的，我们跑了 $\mathcal{O}(n)$ 次双指针算法，所以总时间复杂度是 $\mathcal{O}(n^2)$。
> - 空间复杂度：$\mathcal{O}(n^2)$。
