# 三种方法：最大化得分之差 / 最大化个人得分 / 单调队列优化（Python/Java/C++/Go）

> **[1406. 石子游戏 III](https://leetcode.cn/problems/stone-game-iii/solutions/4001520/san-chong-fang-fa-zui-da-hua-de-fen-zhi-4gcvw/) · Hard · 难度分 2027**

> **题目描述**
> Alice 和 Bob 继续他们的石子游戏。几堆石子 **排成一行** ，每堆石子都对应一个得分，由数组 `stoneValue` 给出。
>
> Alice 和 Bob 轮流取石子，**Alice** 总是先开始。在每个玩家的回合中，该玩家可以拿走剩下石子中的的前 **1、2 或 3 堆石子** 。比赛一直持续到所有石头都被拿走。
>
> 每个玩家的最终得分为他所拿到的每堆石子的对应得分之和。每个玩家的初始分数都是 **0** 。
>
> 比赛的目标是决出最高分，得分最高的选手将会赢得比赛，比赛也可能会出现平局。
>
> 假设 Alice 和 Bob 都采取 **最优策略** 。
>
> 如果 Alice 赢了就返回 `"Alice"` <em>，</em>Bob 赢了就返回 `"Bob"`<em>，</em>分数相同返回 `"Tie"` 。
>
> **示例 1：**
>
> ```
>
> 输入：values = [1,2,3,7]
> 输出："Bob"
> 解释：Alice 总是会输，她的最佳选择是拿走前三堆，得分变成 6 。但是 Bob 的得分为 7，Bob 获胜。
> ```
>
> **示例 2：**
>
> ```
>
> 输入：values = [1,2,3,-9]
> 输出："Alice"
> 解释：Alice 要想获胜就必须在第一个回合拿走前三堆石子，给 Bob 留下负分。
> 如果 Alice 只拿走第一堆，那么她的得分为 1，接下来 Bob 拿走第二、三堆，得分为 5 。之后 Alice 只能拿到分数 -9 的石子堆，输掉比赛。
> 如果 Alice 拿走前两堆，那么她的得分为 3，接下来 Bob 拿走第三堆，得分为 3 。之后 Alice 只能拿到分数 -9 的石子堆，同样会输掉比赛。
> 注意，他们都应该采取 最优策略 ，所以在这里 Alice 将选择能够使她获胜的方案。
> ```
>
> **示例 3：**
>
> ```
>
> 输入：values = [1,2,3,6]
> 输出："Tie"
> 解释：Alice 无法赢得比赛。如果她决定选择前三堆，她可以以平局结束比赛，否则她就会输。
> ```
>
> **提示：**
>
> - `1 <= stoneValue.length <= 5 * 10⁴`
>
> - `-1000 <= stoneValue[i] <= 1000`

> **题解**
> ## 一、寻找子问题
>
> 设 Alice 的最终得分为 $A$，Bob 的最终得分为 $B$。如果 $A > B$，那么 Alice 获胜；如果 $A < B$，那么 Bob 获胜。
>
> $A > B$ 可以变形为 $A-B > 0$，这意味着，我们只需关注得分之差 $A-B$ 的值，而不是 $A$ 和 $B$ 具体是多少。维护一个值，比维护两个值更容易。
>
> 用得分之差的观点来看，为了获胜，Alice 需要最大化 $A-B$，Bob 需要最小化 $A-B$（或者说最大化 $B-A$）。
>
> 也就是说，每个玩家都需要**最大化自己的得分减去对手的得分**。
>
> 为方便描述，下文把 $\textit{stoneValue}$ 简记为 $a$。
>
> 看示例 1，$a = [1,2,3,7]$。枚举 Alice 在第一回合移除的整数：
>
> - 移除 $1$，接下来需要解决的问题是：剩余整数为 $a' = [2,3,7]$，Bob（现在是先手）的得分减去 Alice（现在是后手）的得分最大是多少。
> - 移除 $1,2$，接下来需要解决的问题是：剩余整数为 $a' = [3,7]$，Bob（现在是先手）的得分减去 Alice（现在是后手）的得分最大是多少。
> - 移除 $1,2,3$，接下来需要解决的问题是：剩余整数为 $a' = [7]$，Bob（现在是先手）的得分减去 Alice（现在是后手）的得分最大是多少。
>
> 我们需要解决的子问题，都是**最大化先手的得分减去后手的得分**，都是**和原问题相似的、规模更小的子问题**，所以可以用**递归**解决。
>
> 虽然我们找到了子问题，但是，**原问题和子问题的关系**是什么？怎么利用子问题的结果，算出原问题的答案？
>
> ## 二、状态定义与状态转移方程
>
> 因为要解决的问题都形如「对于 $a$ 的后缀，计算先手得分减去后手得分的最大值」，所以定义 $\textit{dfs}(i)$ 表示当剩余整数为 $a$ 的后缀 $[i,n-1]$ 时，先手得分减去后手得分的最大值。
>
> 例如 $a = [1,2,3,7]$。在第一回合，如果 Alice 移除 $1,2$，那么 Alice 的得分增加
>
> $$
> s = 1 + 2 = 3
> $$
>
> 子问题为：对于 $a' = [3,7]$，Bob 如何操作，可以最大化「Bob 的得分减去 Alice 的得分」。注意这里的得分都是在 $a'$ 上的得分。
>
> 对于 $a'$，设 Bob 的得分为 $B'$，Alice 的得分为 $A'$，那么子问题可以表示为
>
> $$
> \textit{dfs}(2) = B'-A'
> $$
>
> 我们要计算的原问题可以表示为
>
> $$
> \textit{dfs}(0)=A-B
> $$
>
> 二者的关系是什么？
>
> 由于 $A = s + A',\ B = B'$，所以有
>
> $$
> \textit{dfs}(0) = A-B = (s+A') - B' = s - (B'-A') = s - \textit{dfs}(2)
> $$
>
> 即
>
> $$
> \textit{dfs}(0) = s - \textit{dfs}(2)
> $$
>
> 这样就找到了**原问题和子问题的关系**。
>
> 一般地，如果剩余整数为 $a$ 的子数组 $[i,n-1]$，我们枚举先手移除的整数为子数组 $[i,j]$，其中 $i\le j\le \min(i+2,n-1)$，问题变成当剩余整数为 $a$ 的后缀 $[j+1,n-1]$ 时，先手得分减去后手得分的最大值，即 $\textit{dfs}(j+1)$。
>
> 取最大值，得
>
> $$
> \textit{dfs}(i) = \max_{j=i}^{\min(i+2,n-1)} \left(\sum_{k=i}^{j}a[k]\right) - \textit{dfs}(j+1)
> $$
>
> **递归边界**：$\textit{dfs}(n)=0$。此时没有整数，得分之差为 $0 - 0 = 0$。
>
> **递归入口**：$\textit{dfs}(0)$，这是两人得分之差（先手得分减去后手得分）的最大值。
>
> ## 三、递归搜索 + 保存递归返回值 = 记忆化搜索
>
> 考虑到整个递归过程中有大量重复递归调用（递归入参相同）。由于递归函数没有副作用，同样的入参无论计算多少次，算出来的结果都是一样的，因此可以用**记忆化搜索**来优化：
>
> - 如果一个状态（递归入参）是第一次遇到，那么可以在返回前，把状态及其结果记到一个 $\textit{memo}$ 数组中。
> - 如果一个状态不是第一次遇到（$\textit{memo}$ 中保存的结果不等于 $\textit{memo}$ 的初始值），那么可以直接返回 $\textit{memo}$ 中保存的结果。
>
> ⚠**注意**：$\textit{memo}$ 数组的**初始值**一定不能等于要记忆化的值！例如初始值设置为 $0$，并且要记忆化的 $\textit{dfs}(i)$ 也等于 $0$，那就没法判断 $0$ 到底表示第一次遇到这个状态，还是表示之前遇到过了，从而导致记忆化失效。一般把初始值设置为 $-1$，但本题 $\textit{dfs}(i)$ 的返回值可能是负数，可以初始化为 $\infty$ 或 $-\infty$。
>
> > Python 用户可以无视上面这段，直接用 `@cache` 装饰器。
>
> 关于记忆化搜索的原理，请看视频讲解 [动态规划入门：从记忆化搜索到递推【基础算法精讲 17】](https://www.bilibili.com/video/BV1Xj411K7oF/)，其中包含把记忆化搜索 1:1 翻译成递推的技巧。
>
> ```python
> class Solution:
>     def stoneGameIII(self, stoneValue: List[int]) -> str:
>         n = len(stoneValue)
>
>         @cache  # 缓存装饰器，避免重复计算 dfs（一行代码实现记忆化）
>         def dfs(i: int) -> int:
>             if i == n:
>                 return 0
>             res = -inf
>             s = 0
>             for j in range(i, min(i + 3, n)):
>                 s += stoneValue[j]
>                 res = max(res, s - dfs(j + 1))
>             return res
>
>         diff = dfs(0)
>         if diff == 0:
>             return "Tie"
>         return "Alice" if diff > 0 else "Bob"
> ```
>
>
> #### 复杂度分析
>
> - 时间复杂度：$\mathcal{O}(nK)$，其中 $n$ 是 $\textit{stoneValue}$ 的长度，$K=3$ 是每回合玩家可以移除的整数个数。由于每个状态只会计算一次，记忆化搜索的时间复杂度 $=$ 状态个数 $\times$ 单个状态的计算时间。本题状态个数为 $\mathcal{O}(n)$，单个状态的计算时间为 $\mathcal{O}(K)$，所以总的时间复杂度为 $\mathcal{O}(nK)$。
> - 空间复杂度：$\mathcal{O}(n)$。保存多少状态，就需要多少空间。
>
> ## 四、1:1 翻译成递推
>
> 我们可以去掉递归中的「递」，只保留「归」的部分，即自底向上计算。
>
> 具体来说，$f[i]$ 的定义和 $\textit{dfs}(i)$ 的定义是完全一样的，都表示当剩余整数为 $a$ 的后缀 $[i,n-1]$ 时，先手得分减去后手得分的最大值。
>
> 相应的递推式（状态转移方程）也和 $\textit{dfs}$ 一样：
>
> $$
> f[i] = \max_{j=i}^{\min(i+2,n-1)} \left(\sum_{k=i}^{j}a[k]\right) - f[j+1]
> $$
>
> 初始值 $f[n]=0$，翻译自递归边界 $\textit{dfs}(n)=0$。
>
> 两人得分之差（先手得分减去后手得分）的最大值为 $f[0]$，翻译自递归入口 $\textit{dfs}(0)$。
>
> ```python
> class Solution:
>     def stoneGameIII(self, stoneValue: List[int]) -> str:
>         n = len(stoneValue)
>         f = [-inf] * n + [0]
>         for i in range(n - 1, -1, -1):
>             s = 0
>             for j in range(i, min(i + 3, n)):
>                 s += stoneValue[j]
>                 f[i] = max(f[i], s - f[j + 1])
>
>         diff = f[0]
>         if diff == 0:
>             return "Tie"
>         return "Alice" if diff > 0 else "Bob"
> ```
>
>
> #### 复杂度分析
>
> - 时间复杂度：$\mathcal{O}(nK)$，其中 $n$ 是 $\textit{stoneValue}$ 的长度，$K=3$ 是每回合玩家可以移除的整数个数。
> - 空间复杂度：$\mathcal{O}(n)$。
>
> ## 五、另一种状态定义：最大化自己的得分
>
> 自己的得分 + 对手的得分 = 元素总和。
>
> 得分之差 = 自己的得分 - 对手的得分 = 自己的得分 - (元素总和 - 自己的得分) = 自己的得分 × 2 - 元素总和。
>
> 由于元素总和是固定的，所以自己的得分越大，得分之差越大。
>
> 所以，也可以定义 $f[i]$ 表示当剩余整数为 $a$ 的后缀 $[i,n-1]$ 时，先手得分的最大值。
>
> 枚举先手选了子数组 $[i,j]$，那么问题变成当剩余整数为 $a$ 的后缀 $[j+1,n-1]$ 时，后手（变成先手）的得分的最大值，即 $f[j+1]$。
>
> 由于
>
> $$
> 先手得分 + 后手得分 = [i,n-1]\ 的元素和
> $$
>
> 所以
>
> $$
> 先手得分 = [i,n-1]\ 的元素和 - 后手得分
> $$
>
> 后手得分越小，先手得分越大，所以有
>
> $$
> f[i] = \left(\sum_{j=i}^{n-1}a[j]\right) - \min_{j=i}^{\min(i+2,n-1)} f[j+1]
> $$
>
> 初始值 $f[n]=0$。
>
> Alice 的最大得分为 $f[0]$。
>
> 代码实现时，可以创建 $f[n+1] = f[n+2] = 0$，从而简化 $i=n-1$ 和 $i=n-2$ 时的转移。
>
> ```python
> class Solution:
>     def stoneGameIII(self, stoneValue: List[int]) -> str:
>         n = len(stoneValue)
>         f = [0] * (n + 3)
>         suf_sum = 0  # stoneValue 的后缀和
>         for i in range(n - 1, -1, -1):
>             suf_sum += stoneValue[i]
>             f[i] = suf_sum - min(f[i + 1], f[i + 2], f[i + 3])
>
>         diff = f[0] - (suf_sum - f[0])
>         if diff == 0:
>             return "Tie"
>         return "Alice" if diff > 0 else "Bob"
> ```
>
>
> #### 复杂度分析
>
> - 时间复杂度：$\mathcal{O}(nK)$，其中 $n$ 是 $\textit{stoneValue}$ 的长度，$K=3$ 是每回合玩家可以移除的整数个数。
> - 空间复杂度：$\mathcal{O}(n+K)$。
>
> ## 六、空间优化
>
> 用三个变量 $f_1,f_2,f_3$ 分别表示最近的三个 $f$ 值。
>
> ```python
> class Solution:
>     def stoneGameIII(self, stoneValue: List[int]) -> str:
>         suf_sum = f1 = f2 = f3 = 0
>         for val in reversed(stoneValue):
>             suf_sum += val
>             f1, f2, f3 = suf_sum - min(f1, f2, f3), f1, f2
>
>         diff = f1 - (suf_sum - f1)
>         if diff == 0:
>             return "Tie"
>         return "Alice" if diff > 0 else "Bob"
> ```
>
>
> #### 复杂度分析
>
> - 时间复杂度：$\mathcal{O}(nK)$，其中 $n$ 是 $\textit{stoneValue}$ 的长度，$K=3$ 是每回合玩家可以移除的整数个数。
> - 空间复杂度：$\mathcal{O}(K)$。
>
> ## 七、单调队列优化
>
> 转移方程中的
>
> $$
> \min_{j=i}^{\min(i+2,n-1)} f[j+1]
> $$
>
> 本质是在计算长为 $3$ 的**滑动窗口最小值**。做法同 [239. 滑动窗口最大值](https://leetcode.cn/problems/sliding-window-maximum/)，原理请看 [单调队列【基础算法精讲 27】](https://www.bilibili.com/video/BV1bM411X72E/)。
>
> #### 答疑
>
> **问**：为什么这里的三步骤与 239 题不同？
>
> **答**：对于 239 题，$\textit{nums}[i]$ **在**要计算最大值的窗口中，所以要先把 $\textit{nums}[i]$ 放入窗口。而本题 $f[i]$ **不在**要计算最小值的窗口中，所以在计算转移之后，才把 $f[i]$ 放入窗口。
>
> ```python
> class Solution:
>     def stoneGameIII(self, stoneValue: List[int]) -> str:
>         K = 3
>         n = len(stoneValue)
>         f = [0] * (n + 1)
>         q = deque([n])
>         suf_sum = 0  # stoneValue 的后缀和
>
>         for i in range(n - 1, -1, -1):
>             suf_sum += stoneValue[i]
>
>             # 窗口向左滑动
>             # 1. 右边出，保证窗口元素下标在 [i+1, i+K] 中
>             if q[-1] > i + K:  # 离开窗口
>                 q.pop()
>
>             # 2. 计算转移
>             f[i] = suf_sum - f[q[-1]]
>
>             # 3. 左边入，先去掉无用数据，再把 i 入队
>             while q and f[q[0]] >= f[i]:  # f[i] 更小（或者相等）
>                 q.popleft()
>             q.appendleft(i)
>
>         diff = f[0] * 2 - suf_sum
>         if diff == 0:
>             return "Tie"
>         return "Alice" if diff > 0 else "Bob"
> ```
>
>
> #### 复杂度分析
>
> - 时间复杂度：$\mathcal{O}(n)$，其中 $n$ 是 $\textit{stoneValue}$ 的长度。时空复杂度均与 $K$ 无关。
> - 空间复杂度：$\mathcal{O}(n)$。
>
