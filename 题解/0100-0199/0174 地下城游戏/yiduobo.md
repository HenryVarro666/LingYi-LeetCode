# 174. 地下城游戏

祖传的手艺不想丢了，所以按顺序写一个leetcode的题解。计划每日两题，争取不卡题吧。

174.地下城游戏<https://leetcode-cn.com/problems/dungeon-game/>

经典的动态规划问题。由于题目要求行走过程中生命值必须为正，同时地图中部分格子是负值，因此经典的“f[i][j]表示从左上角走到第i行第j列最少需要多少生命值”这种表示方法是不符合最优子结构的，原因是我们可能需要先付出一些生命值，才有机会走到某个能获得极大生命值的房间。因为优先付出了部分生命值，因此在状态转移的过程中是竞争中可能输给其他的走法，但是从这个格子获得的极大生命值可能在后面派上用场从而达成全局最优。

举个例子，地图为：

0 -1 2

0 0 -2

1、f[0][0] \= 1，剩余生命值为1

2、f[0][1] \= 2，剩余生命值为1

3、f[0][2] \= 2，剩余生命值为3

4、f[1][0] \= 1，剩余生命值为1

5、f[1][1] \= 1，这里是因为f[1][0]小于f[0][1]，所以从f[1][0]过来

于是，在这里可以发现，最终f[1][2]会从较小的f[1][1]走过来而不是从f[0][2]走过来，然而这里从f[1][1]走过去需要额外付出2点生命值的代价，但是从f[0][2]走过去则不需要，因此实际上最优解应该是从f[0][2]走过去。

到了这里，有一个想法就是再维护一个g，g[i][j]表示走到f[i][j]时剩余的生命值，然后在状态转移时也将其考虑进去，那么在上面这种情况，在计算f[1][2]时因为g[0][2]能提供较多的生命值，因此会从f[0][2]走过来得到最优解。

很可惜，这样做也是不行的，因为并不是所有的g都能即时生效。

举个例子，在上面这个地图中间再插入一行0，即

0 -1 2

0 0 0

0 0 -2

那么有：

1、f[0][0] \= 1，g[0][0] \= 1

2、f[0][1] \= 2，g[0][1] \= 1

3、f[0][2] \= 2，g[0][2] \= 3

4、f[1][0] \= 1，g[1][0] \= 1

6、f[1][1] \= 1，此时从f[1][0]走过来，那么g[1][1] \= g[1][0] \= 1

7、f[1][2] \= 1，此时从f[1][1]走过俩，那么g[1][2] \= g[1][1] \= 1

可以发现，g在这里已经失去作用了，因为f[1][2]大于等于0，并不需要用到g[0][2]中储存的生命值，因此在这里g[0][2]的生命值并未被g[1][2]继承过来。

做到这里，又有一个想法是除了f与g，再维护两个数组表示走到第i行第j列所能从地图中白嫖的最大生命值以及为了白嫖这些生命值需要付出的最初生命是多少。很遗憾，这样做也有问题，因为生命值够用就好，并不需要白嫖到最大值，换言之，在状态转移的过程中，并不能确定此时应该以最小代价优先还是以最大生命值优先。

于是，经典的“f[i][j]表示从左上角走到第i行第j列最少需要多少生命值”这种表示方法就行不通了。

但是，之前考虑到的生命值够用就好带来了一些启发。我们可以从终点开始往回做动态规划，此时的f[i][j]表示从第i行第j列开始，至少需要多少生命值才能走到终点。这样一来，为后面的负数格子累积生命值这个概念就已经隐含在状态中了。

状态转移变成了从正下方或者正右方，需要注意判断如果当前格子为正数时可能导致计算出来f[i][j]小于等于0的情况，那么此时f[i][j]应该取1。

最后附上python代码：

```python
class Solution(object):
    def calculateMinimumHP(self, dungeon):
        """
        :type dungeon: List[List[int]]
        :rtype: int
        """

        m = len(dungeon)
        n = len(dungeon[0])

        f = [[0] * n for _ in range(m)]

        for i in range(m - 1, -1, -1):
            for j in range(n - 1, -1, -1):
                if i == m - 1:
                    if j == n - 1:
                        f[i][j] = 1
                    else:
                        f[i][j] = f[i][j + 1]
                elif j == n - 1:
                    f[i][j] = f[i + 1][j]
                else:
                    f[i][j] = min(f[i + 1][j], f[i][j + 1])
                    
                f[i][j] = max(1, f[i][j] - dungeon[i][j])

        return f[0][0]
```
