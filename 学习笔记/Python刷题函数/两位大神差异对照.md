## 2. Python 用法差异详解

只讲有差异的点：要么只有一方用，要么两人写法明显不同。每节给出两人的典型写法（真实代码摘录）、差异原因、各自优缺点和面试推荐写法。函数本身的用法见 [Python 刷题函数从零讲解](Python%20刷题函数从零讲解.md)。

### 2.1 外壳：`class Solution(object)` + docstring vs 类型注解

> 普查：`class X(object)` 灵神 **1** 篇 · yiduobo **3618** 篇；docstring `:type` **0** · **3622**；类型注解 **2276** · **0**

```py
# yiduobo 0001
class Solution(object):
    def twoSum(self, nums, target):
        """
        :type nums: List[int]
        :type target: int
        :rtype: List[int]
        """
```

```py
# 灵神 0001
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
```

- **原因**：LeetCode 有 "Python"（2.7）和 "Python3" 两个语言选项。yiduobo 从 2020 年开始一直用前者的默认模板，灵神用后者。
- **优缺点**：类型注解让参数类型一目了然，编辑器能提示；docstring 也写了类型，但只是注释。外壳本身不影响对错，真正要小心的是外壳下面的 Python 2 语义（2.2 节和 2.14 节）。
- **面试推荐**：Python 3 外壳。类型注解写不写都行，写上显得规范。

### 2.2 整数除法：`//` vs `/`（最大的坑）

> 普查：`//` 灵神 **469** 篇 · yiduobo **257** 篇；`/` 灵神 **42** 篇（85 次）· yiduobo **546** 篇（955 次）

反过来，yiduobo 需要小数时得手动转成浮点：

```python
print(-7 // 2, int(-7 / 2))   # -4 -3   （// 向下取整；int() 向零截断）
```

- **原因**：Python 2 中 `int / int` 向下取整；Python 3 中 `/` 永远是真除法（结果为 float），`//` 才是向下取整。census 里 yiduobo 使用 `//` 的示例文件是 2639，说明他较新的题解已经开始用 `//`，但 Hot100 这批（2020～2021 年写的）基本都是 `/`。
- **后果分三类**：
  1. 直接 `TypeError`：float 不能做 `range` 参数、下标、切片长度、列表乘法次数（yiduobo 0054、0048、0108、0416、0031）。
  2. 结果变成 float：0015 的三元组里出现 `1.0`；0062 的组合数变成 float；0002 的进位 `add_flag` 变成 1.5 这样的小数，整条结果链表都会错。
  3. 静默错误：0005 的 `f[index] / 2 * 2` 本意是"向下取偶"，在 Python 3 里等于原值，不报错但长度算错。
- **面试推荐**：下标、计数、中点一律用 `//`；确实要小数才用 `/`。Python 整数不会溢出，求中点直接 `(l + r) // 2`，不必写 yiduobo 0033 那种 C/Java 防溢出写法 `(right - left) / 2 + left`。对负数要记住 `//` 向下取整，`int(a / b)` 向零截断。

- **原因**：`math.inf` 从 Python 3.5 才有。yiduobo 的习惯是用整数大数或语义哨兵（`None`、`-1`），而不是 `float('inf')`。
- **优缺点**：
  - `inf` 让边界统一、分支少：灵神 0053 用 `ans = -inf` 一套代码覆盖全负数组，yiduobo 需要先特判。但 `inf` 是 float，不能做下标、不能 `range`，两个 inf 相减得 `nan`。

  - `None` 语义清楚，代价是到处 `is None` 判断；`-1` 哨兵和 `min` 一起用时要多写条件（yiduobo 0322 那一行有三个条件）。
- **面试推荐**：最值初始化用 `inf / -inf`（或 `float('inf')`）；DP 的不可达状态用 `inf`，最后 `ans if ans < inf else -1`。

```python
s = "abca"
d1 = {}
for c in s:
    d1[c] = d1.get(c, 0) + 1      # yiduobo 风格

for c in s:
    d2[c] += 1                    # 灵神 风格一

print(d1 == d2 == d3)             # True
print(d3.most_common(1))          # [('a', 2)]

# 滑动窗口里计数会减到 0：

win["c"] -= 1                     # 'c' 离开窗口，计数变 0 但键还在
target = Counter("ab")
print(win == target)              # True   （Python 3.10+：Counter 比较把 0 当作不存在）
print(dict(win) == dict(target))  # False  （普通 dict 会被残留的 'c': 0 坑到）
print(Counter("aabc") >= Counter("abc"))  # True   （3.10+ 支持 >= 表示"涵盖"，灵神 0076/0079）
```

- **原因**：Python 2.7 其实也有 `Counter` 和 `defaultdict`，yiduobo 更多是习惯；他用 `Counter` 的 30 篇集中在较新的题号（census 示例为 2983）。
- **优缺点**：
  - `Counter` 一行完成统计，支持 `most_common`、`==`、`>=`。但比较时忽略 0 计数是 Python 3.10 才有的行为，所以灵神 0438 特意注释"请选择 Python3 提交代码，而不是 Python"。yiduobo 0438 用普通 dict，只能逐键比较，因为窗口里会残留计数为 0 的键。
  - `defaultdict` 读一个不存在的键会把它**插入**字典，`in` 判断会被污染，遍历时读取新键还可能报"字典大小改变"。灵神 0076 注释"defaultdict 比 Counter 快"。
  - `.get(k, 0)` 最朴素、不依赖版本、行为最明确，代价是代码长。
- **面试推荐**：计数用 `Counter` 或 `defaultdict(int)`；需要比较两个计数表时说明 3.10+ 的语义，或者干脆用长度 26 的数组。

> 普查：`@cache` 灵神 **223** 篇 · yiduobo **0**；`.cache_clear()` **19** · **0**；`lru_cache` 两人都没有



```py

...
```

yiduobo 的 DP 题大多直接写递推（0322、0416、1143、0072），很少写递归。

```python
from functools import cache

# 灵神风格：@cache 一行搞定记忆化
@cache
def fib(n: int) -> int:
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(100))           # 354224848179261915075
print(fib.cache_info())   # CacheInfo(hits=98, misses=101, maxsize=None, currsize=101)
fib.cache_clear()         # 多组数据共用一个 dfs 时，可手动清空

# yiduobo 风格：自己开表，None 表示"还没算过"（对应 yiduobo 0131 的 f[left][right]）
def fib2(n, memo=None):
    if memo is None:
        memo = [None] * (n + 1)
    if n < 2:
        return n
    if memo[n] is None:
        memo[n] = fib2(n - 1, memo) + fib2(n - 2, memo)
    return memo[n]

print(fib2(100))          # 354224848179261915075
```

- **原因**：`functools.lru_cache` 从 Python 3.2 开始有，`functools.cache` 从 3.9 开始有，Python 2 都没有。灵神的教学路线是"递归 → 记忆化 → 递推 → 空间优化"，`@cache` 是第二步的一行实现。
- **优缺点**：`@cache` 能最快写出正确解，但递归深度默认上限约 1000，参数必须可哈希；多个测试用例之间要么 `cache_clear()`，要么像灵神 0279 那样故意把 dfs 写在类外面共享结果。手写表或递推没有递归开销，还能继续做空间优化。
- **面试推荐**：先讲清状态定义和转移方程。写 `@cache` 记忆化完全可以，但要能当场 1:1 翻译成递推，面试官常追问空间优化。

## 3. Hot100 逐题解法差异

**怎么读这些表**

- "灵神解法"列写主写法（题解中的方法一，或标题点名的方法），其余写法注明"另有 X 写法"。
- 复杂度一般写作"时间 / 空间"（空间不关键时只写时间），按各自代码的实际情况给出，不只照抄作者自己的分析。
- 两人思路相同时，"关键差异"列写"思路相同"，再指出实现细节差异：边界写法、数据结构、是否原地、是否用库函数，以及 yiduobo 代码搬到 Python 3 的问题。
- "面试推荐"是综合两人后给出的建议，不一定是灵神的主写法。

### 3.1 哈希

链表题两人的算法几乎都一样，最明显的差异是**哨兵**：灵神几乎每题都用 dummy 节点消除头节点特判，yiduobo 有时用"假头"、有时用特判（0002、0019）。另一个差异是模块化：灵神把 876 / 206 / 21 写成独立函数在 234、148 里复用，yiduobo 每题内联。

有意思的是，"堆"分类下的 215 两人都没有用堆，347 也只有 yiduobo 用了堆。295 最能体现版本差异：同一个双堆思路，灵神借助 3.14 的最大堆 API 和 `heappushpop` 把分类讨论合成两行，yiduobo 用取负 + 三分支。

## 4. 结论

### 4.1 各自适合什么场景

| | 灵神 | yiduobo |
|---|---|---|
| 最适合 | 建立模板、刷题量大时快速 AC、面试前集中复习、学 Python 3 新特性 | 理解"为什么对"、看严格推导、拓宽思路（另类解法）、练习读 C 风格代码 |
| 强项 | 一题多解、循环不变量讲得清楚、复杂度分析完整、配套题单 | 推导和证明写得细（0001 双指针三种情况、0011 短板论证、0142 入环点推导、0072 操作等价性）；常直接给进阶解（0114、0148、0230、0238 的 O(1) 空间版） |
| 要注意 | 依赖 LeetCode 自动导入和新版本特性（Counter 比较 3.10+、`bisect` 的 `key=` 3.10+、`heappush_max` 3.14+），本地或面试环境可能跑不了 | Python 2 语法（`/`、`print`、`Queue`、`cmp`），照抄到 Python 3 可能报错或静默算错；部分 Morris 写法会破坏输入 |

### 4.2 怎么取长补短

1. **主线用灵神**：每道题先读灵神的主写法，背下模板（滑窗三步、lower_bound + 转化表、单调栈、回溯的两种视角、DP 的"记忆化 → 递推 → 空间优化"四步）。
2. **推导看 yiduobo**：再读 yiduobo 题解的文字部分。他的代码常常不是最优写法，但"为什么可以这样做"往往讲得更细，正好补上模板背后的理由。
3. **另类解法当追问储备**：yiduobo 的 0022 卡特兰递推、0279 四平方和定理、0076 位置表跳跃、0070 矩阵快速幂、0005 Manacher，面试官问"还有别的做法吗"时拿得出来。
4. **抄 yiduobo 代码前过一遍 2.14 节清单**：重点搜 `/`，其次是堆里的元组、`global`、返回的 `dict.values()`。
5. **面试时的"合体写法"**：Python 3 外壳 + 灵神的模板结构 + 能被面试官看懂的显式表达；二分要能手写（固定一种区间），计数用 `Counter` 或数组，堆用 `heapq` 加取负，记忆化写完要能翻译成递推；讲解时用 yiduobo 式的推导说明正确性。

一句话：**用灵神的模板写代码，用 yiduobo 的推导讲思路。**
