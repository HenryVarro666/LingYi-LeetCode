## 一、题目用大白话说

桌上摆着一排盒子，每个盒子里有几颗糖，数量都是正数。你要拿走**挨在一起**的几个盒子，让糖的总数至少是 `target` 颗。问：最少拿几个盒子？如果全拿走都不够，答案是 0。

题目里的"子数组"就是"挨在一起的一段"。`[2,3,1]` 里，`[2,3]` 是子数组，`[2,1]` 不是，因为中间跳过了 3。

示例 1：

```
输入：target = 7, nums = [2,3,1,2,4,3]
输出：2
```

最后两个盒子 `[4,3]` 加起来正好 7 颗，只用了 2 个盒子。没有哪一个盒子单独就有 7 颗，所以 2 是最少的。

## 二、思路

**最笨的办法**：把每个盒子都当一次起点，从它开始往右一个个加，加到够 7 为止，记下用了几个盒子。6 个盒子要试 6 个起点，每个起点最多往右走 6 步。题目里盒子最多有 10 万个，10 万个起点各走 10 万步是 100 亿步，太慢。

笨办法慢在重复劳动：起点从第 0 个换到第 1 个时，中间那些盒子的糖又从头加了一遍。

**灵茶的办法**：用两只手在这排盒子上框出一段，这一段叫"窗口"。

- 右手每次往右挪一格，把新盒子框进来。
- 每框进一个新盒子，就试着把左手往右收：如果丢掉最左边那个盒子后糖还够，就丢掉它。一直收到不能再收。
- 这时如果框里的糖够数，框的宽度就是一个候选答案，和之前的最小纪录比一比。

两只手都只往右走，从不回头，所以总共走不了多少步。

这个办法成立靠的是"每盒糖都是正数"：框进一个盒子，总数一定变多；丢掉一个盒子，总数一定变少。

类比和代码的对应关系：

| 类比 | 代码 |
| --- | --- |
| 右手的位置 | `right` |
| 左手的位置 | `left` |
| 右手刚框进来的那盒糖的数量 | `x` |
| 框里现在的糖数 | `s` |
| 目前为止的最小纪录 | `ans` |
| 盒子总数 | `n` |

## 三、完整代码

```python
class Solution:
    def minSubArrayLen(self, target: int, nums: List[int]) -> int:
        n = len(nums)
        ans = n + 1  # 也可以写 inf
        s = left = 0
        for right, x in enumerate(nums):  # 枚举子数组右端点
            s += x
            while s - nums[left] >= target:  # 尽量缩小子数组长度
                s -= nums[left]
                left += 1  # 左端点右移
            if s >= target:
                ans = min(ans, right-left+1)
        return ans if ans <= n else 0
```

## 四、变量表

| 变量 | 存的是什么 | 初始值和原因 | 什么时候变 |
| --- | --- | --- | --- |
| `target` | 题目给的目标，糖至少要这么多 | 由题目传入 | 不变 |
| `nums` | 题目给的列表，`nums[i]` 是第 `i` 个盒子的糖数。编号从 0 开始 | 由题目传入 | 不变 |
| `n` | 盒子的个数 | `len(nums)` | 不变 |
| `ans` | 到目前为止找到的最短长度 | `n + 1`。真正的答案最大是 `n`，所以 `n + 1` 表示"还没找到" | 第 12 行，找到更短的窗口时变小 |
| `s` | 窗口里所有数的和 | `0`，一开始窗口是空的 | 第 7 行加上新数，第 9 行减去丢掉的数 |
| `left` | 窗口最左边那个数的下标 | `0`，从最左边开始 | 第 10 行，每丢掉一个数就加 1 |
| `right` | 窗口最右边那个数的下标 | 由 `for` 循环给出，第一轮是 0 | 每轮循环加 1 |
| `x` | 这一轮新进窗口的数，等于 `nums[right]` | 由 `for` 循环给出 | 每轮循环换成下一个数 |

下标的意思是"第几个"，从 0 数起。`nums = [2,3,1,2,4,3]` 里，`nums[0]` 是 2，`nums[4]` 是 4。

## 五、逐行讲解

**第 1 行**　`class Solution:`

- 做什么：定义一个叫 `Solution` 的类。类可以理解成一个装函数的盒子。
- 为什么：这是力扣的固定格式。力扣会创建一个 `Solution`，再调用里面的函数。这一行照抄就行。

**第 2 行**　`def minSubArrayLen(self, target: int, nums: List[int]) -> int:`

- 做什么：定义函数 `minSubArrayLen`，它接收 `target` 和 `nums`，最后返回一个整数。
- 语法：`self` 是写在类里的函数必须带的第一个参数，这道题用不到它。`target: int` 里冒号后面的 `int` 是类型提示，意思是"这里应该传整数"。`List[int]` 是"装整数的列表"。`-> int` 是"返回值是整数"。类型提示只给人看，删掉也能运行。

**第 3 行**　`n = len(nums)`

- 做什么：数一数 `nums` 里有几个数，存进 `n`。示例 1 里 `n` 是 6。
- 为什么：第 4 行和第 13 行都要用到这个个数，先算好存起来。

**第 4 行**　`ans = n + 1  # 也可以写 inf`

- 做什么：把 `ans` 设成 7（6 + 1）。
- 为什么：`ans` 要记录"最短长度"，后面每次都拿新长度和它比，谁小留谁。初始值必须比所有可能的答案都大，否则第一次比较就会出错。窗口最长就是整个列表，长度 `n`，所以 `n + 1` 一定够大。最后如果 `ans` 还是 `n + 1`，说明从没找到过合格的窗口。
- 语法：`#` 后面是注释，给人看的，程序不执行。注释里的 `inf` 是"无穷大"，写成 `ans = inf` 效果一样。

**第 5 行**　`s = left = 0`

- 做什么：把 `s` 和 `left` 都设成 0。
- 语法：`a = b = 0` 是连续赋值，等于写两行 `s = 0` 和 `left = 0`。
- 为什么：一开始窗口里什么都没有，和是 0。左手放在最左边，下标 0。

**第 6 行**　`for right, x in enumerate(nums):  # 枚举子数组右端点`

- 做什么：从左到右把 `nums` 里的数一个个取出来。每一轮，`right` 是这个数的下标，`x` 是这个数本身。
- 语法：`enumerate` 会同时给出"第几个"和"是什么"。

  ```python
  for i, v in enumerate([2, 3, 1]):
      print(i, v)   # 依次打印：0 2、1 3、2 1
  ```

- 为什么：右手每轮往右挪一格，这就是"把新盒子框进来"。用 `enumerate` 是因为下标和数值都要用：数值用来加进 `s`，下标用来算窗口长度。

**第 7 行**　`s += x`

- 做什么：把新进来的数加到 `s` 上。`s += x` 就是 `s = s + x`。
- 为什么：窗口多了一个数，和也要跟着更新。这样不用每次把窗口里的数重新加一遍。

**第 8 行**　`while s - nums[left] >= target:  # 尽量缩小子数组长度`

- 做什么：`nums[left]` 是窗口最左边的数。这一行在问："如果丢掉最左边的数，剩下的和还够 `target` 吗？"够的话就进循环去丢，不够就跳过。
- 为什么是 `while` 不是 `if`：可能要连丢好几个。示例 1 里右手走到 4 时，要连丢 2 和 3 两个数。`if` 只能丢一次。
- 为什么是 `>=` 不是 `>`：题目要求"和大于等于 `target`"，正好等于也算合格。
- 为什么先问再丢：这样保证丢完以后窗口仍然合格，第 11 行看到的是"合格窗口里最短的那个"。
- `left` 会不会跑到 `right` 右边去：不会。当窗口里只剩一个数时，`s` 就等于 `nums[left]`，`s - nums[left]` 是 0，而 `target` 至少是 1，条件不成立，循环停下。

**第 9 行**　`s -= nums[left]`

- 做什么：从 `s` 里减掉最左边的数。
- 为什么：这个数要被丢出窗口了，和里不能再算它。

**第 10 行**　`left += 1  # 左端点右移`

- 做什么：`left` 加 1，左手往右挪一格。
- 为什么：和第 9 行是一对。第 9 行改了和，这一行改了窗口的左边界。
- 顺序能不能换：不能。如果先 `left += 1` 再 `s -= nums[left]`，减掉的就是新的最左边的数，减错了。

**第 11 行**　`if s >= target:`

- 做什么：检查现在窗口里的和够不够。
- 为什么还要检查：第 8 行的 `while` 只保证"能丢就丢"，不保证窗口合格。刚开始的几轮，窗口里的数太少，和根本不够，这时不能记录长度。示例 1 的前三轮都是这种情况。

**第 12 行**　`ans = min(ans, right-left+1)`

- 做什么：算出当前窗口的长度 `right-left+1`，和 `ans` 比，把小的那个存回 `ans`。
- 为什么是 `right-left+1`：下标 2 到下标 4 是 2、3、4 三个数，4 - 2 = 2，少数了一个，所以要加 1。
- 语法：`min(a, b)` 返回两个数里小的那个。

**第 13 行**　`return ans if ans <= n else 0`

- 做什么：如果 `ans` 不超过 `n`，返回 `ans`；否则返回 0。
- 语法：`A if 条件 else B` 是一行写完的判断。条件成立取 A，不成立取 B。
- 为什么：`ans` 还是 `n + 1` 说明第 12 行一次都没执行过，没有合格的窗口，题目要求这时返回 0。
- 注意缩进：这一行和 `for` 对齐，所以是整个循环结束后才执行。

## 六、手算演示

输入：`target = 7`，`nums = [2,3,1,2,4,3]`。进入循环前：`n = 6`，`ans = 7`，`s = 0`，`left = 0`。

下表每一行是 `for` 循环的一轮，数值是这一轮结束时的状态，来自实际运行代码的输出。

| `right` | `x` | 加上 `x` 后的 `s` | `while` 丢了几个 | `left` | `s` | 窗口 | `ans` | 发生了什么 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | 2 | 2 | 0 | 0 | 2 | `[2]` | 7 | 和不够 7，不记录 |
| 1 | 3 | 5 | 0 | 0 | 5 | `[2,3]` | 7 | 和不够，不记录 |
| 2 | 1 | 6 | 0 | 0 | 6 | `[2,3,1]` | 7 | 和不够，不记录 |
| 3 | 2 | 8 | 0 | 0 | 8 | `[2,3,1,2]` | 4 | 丢掉 2 只剩 6，不能丢。和够了，长度 4 |
| 4 | 4 | 12 | 2 | 2 | 7 | `[1,2,4]` | 3 | 丢 2 剩 10，丢 3 剩 7，再丢 1 只剩 6，停。长度 3 |
| 5 | 3 | 10 | 2 | 4 | 7 | `[4,3]` | 2 | 丢 1 剩 9，丢 2 剩 7，再丢 4 只剩 3，停。长度 2 |

循环结束，`ans = 2`，不超过 `n = 6`，返回 2，和题目给的输出一致。

最值得看的是 `right = 4` 那一轮：`while` 连续执行了两次，`left` 从 0 跳到 2。这就是第 8 行必须用 `while` 的原因。

## 七、小白容易错的地方

1. **把第 8 行写成 `while s >= target:`，其他不动。** 这样 `while` 会一直丢到和不够为止，到第 11 行时 `s >= target` 永远不成立，`ans` 从不更新，函数永远返回 0。`while s >= target` 是写法二的条件，要配合写法二的更新位置用，见第九节。
2. **长度写成 `right - left`。** 少算一个，示例 1 会返回 1。正确是 `right - left + 1`。
3. **漏掉第 11 行的 `if`。** 第一轮窗口是 `[2]`，和不够 7，但长度 1 会被记进 `ans`，最后返回 1。
4. **最后直接 `return ans`。** 示例 3（`target = 11`，八个 1）里没有合格窗口，会返回 9，而题目要求返回 0。
5. **第 9、10 行写反。** 先移动 `left` 再减，减掉的是错误的数，`s` 就和窗口对不上了。

## 八、复杂度

**时间复杂度 O(n)。** 这个记号的意思是：操作次数和 `n` 成正比，`n` 翻倍，用时大约也翻倍。

代码里 `for` 套着 `while`，看起来像是"每轮都可能走很多步"。但要数的是 `left += 1` 总共执行了几次。`left` 从 0 开始，只增不减，最大到 `n - 1`，所以整个程序跑下来，`while` 里面的代码加起来最多执行 `n` 次。`for` 循环本身走 `n` 轮。两者相加大约是 `2n` 步，和 `n` 成正比。

示例 1 里 `n = 6`，`while` 一共只执行了 4 次（表里"丢了几个"那一列加起来）。

**空间复杂度 O(1)。** 意思是不管 `nums` 多长，额外用到的变量就是 `n`、`ans`、`s`、`left`、`right`、`x` 这几个，数量固定。

## 九、其他写法

### 写法二：在 while 循环内更新答案

```python
class Solution:
    def minSubArrayLen(self, target: int, nums: List[int]) -> int:
        n = len(nums)
        ans = n + 1  # 也可以写 inf
        s = left = 0
        for right, x in enumerate(nums):  # 枚举子数组右端点
            s += x
            while s >= target:  # 满足要求
                ans = min(ans, right - left + 1)
                s -= nums[left]
                left += 1  # 左端点右移
        return ans if ans <= n else 0
```

第 1 到 7 行、最后一行和写法一完全一样。不同的是第 8 到 11 行。

**第 8 行**　`while s >= target:  # 满足要求`

- 做什么：只要窗口现在是合格的，就进循环。
- 和写法一的区别：写法一问的是"丢掉一个以后还合格吗"，这里问的是"现在合格吗"。

**第 9 行**　`ans = min(ans, right - left + 1)`

- 做什么：窗口合格，先把长度记下来。
- 为什么放在循环里：进了循环就说明窗口合格，所以不再需要写法一第 11 行的 `if`。而且必须在丢数之前记录，丢完就可能不合格了。

**第 10、11 行**　`s -= nums[left]` 和 `left += 1`

- 做什么：丢掉最左边的数，和写法一的第 9、10 行一样。
- 区别在效果：这里会一直丢到窗口**不合格**为止。每轮 `for` 结束时，写法一的窗口是合格的（只要曾经够数），写法二的窗口是不合格的。

同样的输入，写法二每轮结束时的状态（实际运行输出）：

| `right` | `x` | `left` | `s` | `ans` |
| --- | --- | --- | --- | --- |
| 0 | 2 | 0 | 2 | 7 |
| 1 | 3 | 0 | 5 | 7 |
| 2 | 1 | 0 | 6 | 7 |
| 3 | 2 | 1 | 6 | 4 |
| 4 | 4 | 3 | 6 | 3 |
| 5 | 3 | 5 | 3 | 2 |

`ans` 那一列和写法一完全相同，最终都返回 2。前三轮和还不够 7，两种写法的 `left` 都停在 0。从 `right = 3` 开始，写法二的 `left` 每轮都比写法一多 1（1 对 0，3 对 2，5 对 4），因为它多丢了一个数。

两种写法答案永远相同。写法二少一个 `if`，代码短一行。写法一的好处是循环结束后 `left` 到 `right` 正好是一个合格窗口，想顺便知道"是哪一段"时更方便。

## 十、和你的写法对比

[209.py](../../我的代码/209.py) 里有两段代码，分别对应上面的写法一和写法二，逻辑和灵茶写法一致。

唯一的差别在你的第二段：初始值写的是 `ans = inf`，灵茶写的是 `ans = n + 1`。两者效果相同，因为 `inf <= n` 不成立，最后同样返回 0。在力扣上 `inf` 可以直接用；在自己电脑上运行需要先写 `from math import inf`。

你在第一段里加的注释"当 left=right，子数组的长度为 1"是对的，它解释的正是 `right-left+1` 里为什么要加 1。
