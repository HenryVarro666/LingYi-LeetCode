灵魂公式：四步握手法 (The Four-Step Handshake)
要在两个现有节点 PRED (前驱) 与 SUCC (后继) 之间插入新节点 X，请遵循以下顺序以确保逻辑安全：

X.prev = PRED：新节点向左看，建立与前辈的联系。
X.next = SUCC：新节点向右看，建立与后辈的联系。
PRED.next = X：前辈将右手交给新节点。
SUCC.prev = X：后辈将左手交给新节点。
遵循“先外后内”原则（先处理新节点 X 的指针，再修改 PRED/SUCC 的指向），即使操作中断，原链表结构依然完整，不会发生内存丢失。

不同情境的 PRED 与 SUCC 定位
利用 Dummy Nodes (虚拟节点)，我们可以消除 None 判断，统一代码：

| 操作场景 | PRED (插入点的前驱) | SUCC (插入点的后继) |
| --- | --- | --- |
| addAtHead | self.head (虚拟头) | self.head.next |
| addAtTail | self.tail.prev | self.tail (虚拟尾) |
| addAtIndex | 从 head 走 index 步到达的节点 | PRED.next |

## 在刷题过程中常见的三个误区，希望新手可以避免。

- 刷题看数量不看质量
这是新手最容易犯的错误，很多人刷题总是只看数量，以为刷的多就行，实际上质量比数量更重要！那什么叫高质量刷题呢？这里举几个例子(1) **4. 寻找两个正序数组的中位数** 这道题很多萌新其实连题目要求都没看懂，嚷嚷两句简单就过了，实际上这题算是个“君子游戏”，其中O(logN)的方法我到现在都不觉得容易。(2) **53. 最大子数组和** 题目本身不难，但如果能再进一步，完成题目的进阶要求的话，就有望完成周赛399 T4，一道接近2700分的难题。(3)**300. 最长递增子序列** 这道题的方法包括A、O(N2)的动态规划，B、O(NlogN)的贪心加二分查找，假如做题是打怪，学会方法A能获得10点经验值，那么方法B则相当于50点经验值！也就是说，如果你高质量的刷1题，胜过低质量的刷3道甚至5道题！当然，值得高质量刷的题远不止我提到的，想要高质量的刷需要耐心和积累。

关于1，LIS的例子很好，nlogn做法没见过不太容易想到，但这对于面试已经几乎是硬性要求，最好能领悟到这个贪心做法的妙处，而不是死记代码。对于53题这个经典DP，大多数人会基础做法就够了，那个进阶对LC而言要求太高了。再补充几个非常经典的多种方法都该掌握的：32（栈模拟，DP，贪心），42（暴力，单调栈，双指针），62（DP，组合数学），206（迭代，递归，尾递归），253（优先队列，差分数组）（没会员去2406，一样的题），264（优先队列，DP）。

- 刷题追求所谓的击败100%
LeetCode上做完题一般会告诉你代码运行的时间和空间情况，并附上一个击败xx%的数字，不少人会盲目的追求刷上一个高数字并把此作为衡量代码好坏的一个标准，实际上绝大多数高水平算法选手都不把这个当回事。而对于新手，这个数字没有任何参考意义！算法学习者真正要做的是能正确分析自己代码的时空复杂度（时间和空间都要分析）。（PS：根据我个人观察，如果一篇题解写自己击败了100%，80%的情况下这篇题解会是篇垃圾题解）

关于2，所谓的100%几乎都是过拟合，一旦增加case往往就不再100%（甚至直接炸掉，488被专业叉人的大佬交了一堆数据，当年的前排全军覆没），做题最重要的是正确性和复杂度，时间有限没必要纠结一些奇怪的东西。

- 追求所谓的一行流
部分新人不时陷入所谓一行两行解决问题炫技。不能说一行流两行流没技术含量，但是对于算法学习而言，所谓一行流两行流是没有价值的。新手要做的是把代码写的简洁，能去掉冗余就够了。过于简短的代码，不仅对算法学习没有裨益，在实际业务中更是由于没有可读性可以直接划为垃圾。更何况很多所谓一行代码实际上以暴力的手段代替掉有深度的算法（例如排序里，冒泡排序比快排、堆排和归并排序简短得多，但从算法角度，冒泡排序价值是最低的）。

关于3，希望所有新手能明白，这种代码整活意义大于实际意义，【不应该】刻意模仿，面试这样做很有可能回家等通知+人才库，因为这和工程代码的原则背道而驰。

一个更好的思考链路应该是这样的：

1. 确保读懂题目并且把normal case和edge case都想一想怎么得出正确答案
2. 在不考虑时间或者空间复杂度的情况下，想出暴力解。这里我要非常的强调，千万千万千万不要小看暴力解。因为能得出暴力解说明至少你读懂了题目要什么和你要干什么

3. 以暴力解为锚点，思考暴力解最慢的瓶颈在哪里。
4. 知道瓶颈在哪里之后，就可以有针对性的思考怎么解决瓶颈。举一个例子，假设一个暴力姐需要我们枚举每个元素的时候都要遍历元素的左边来找到左边的最小值，那么这个暴力解最慢的瓶颈就在于每次都要重复的向左遍历，于是我们就可以想到用前缀最小来优化时间复杂度。

5. 在新的思路下重新思考题解，注意过程中的细节和确保edge case能过。
在使用以上思路的时候，认真体会这句话： **算法的本质就两种：聪明的枚举（枚举右维护左，哈希表，前缀，前缀和等等）和无遗漏（DFS/BFS/DP等等）的枚举**。

以上思路是我个人现阶段的一些总结，希望能在大框架上帮助新手快速形成自己的思维框架。

个人的瓶颈：

可以总结为对题目的剖析不够充分，时常卡壳找不到思路。希望有大神可以帮忙指点一下问题所在，或者提供一些总结经验的方法。
